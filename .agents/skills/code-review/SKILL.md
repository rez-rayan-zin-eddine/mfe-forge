# Code review

## When to use

Before handoff, commit, PR, or when reviewing another change.

## Inputs and context required

Final diff, tests, public APIs, docs, and task acceptance criteria.

## Procedure

1. Check correctness and failure paths. 2. Check type/API compatibility. 3. Check idempotency and security-sensitive mutations. 4. Check tests and docs. 5. Classify findings by severity.

## Verification

Diff check, focused regression tests, and acceptance-criteria checklist.

## Expected artifacts

Review findings, severity, file/line references, and approval/blocker status.
