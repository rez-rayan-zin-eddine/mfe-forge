# Implementation strategy

## When to use

Any non-trivial feature, refactor, or bug fix.

## Inputs and context required

User outcome, affected APIs, existing tests, and constraints.

## Procedure

1. Define outcome and non-goals. 2. Map dependencies and compatibility risk. 3. Split into smallest waves. 4. Implement one wave at a time. 5. Reassess after each verification step.

## Verification

Focused tests, package type-check/build, and a final diff review.

## Expected artifacts

Implementation plan, changed modules, tests, and explicit follow-up items.
