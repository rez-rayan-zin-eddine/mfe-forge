# MFE Forge

[![npm version](https://img.shields.io/npm/v/mfe-forge.svg)](https://www.npmjs.com/package/mfe-forge)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

> CLI and runtime packages for Vite + React micro-frontends using Module Federation (pre-1.0)

MFE Forge scaffolds scoped hosts and remotes, discovers project topology, keeps host federation remotes and type declarations in sync, and ships small runtime packages for loading and coordinating MFEs.

> **Status:** `0.x` development line. APIs and generated templates may change between minor versions. Versions `2.0.0`–`8.1.0` on npm are deprecated prototype releases — use `0.1.0` or later.

## Quick start

```bash
npx mfe-forge init my-project
cd my-project
npx mfe-forge generate host checkout/host
npx mfe-forge generate app checkout/cart
npx mfe-forge sync
npm run dev
```

Apps and hosts use `scope/name` paths; a host automatically registers the remotes in its scope.

## Installation

```bash
npm install -g mfe-forge     # global: `mfe-forge` and `mfe` binaries
npm install -D mfe-forge     # project-local
```

Requires Node.js 20+ (or Bun).

## Commands

| Command | Purpose |
| --- | --- |
| `init [name]` | Create a workspace (`--template`, `--package-manager <bun\|pnpm\|npm>`, `--skip-install`, `--skip-git`) |
| `generate <type> [name]` (`g`) | Generate `app`, `host`, `package`/`pkg`, `library`, or `design-system` (`--port`, `--host`, `--scope`, `--features`, `--skip-host`, `--dry-run`) |
| `dev` | Start apps (`--app`, `--scope`, `--host-only`); multi-app mode uses `concurrently` |
| `build [app]` | Build discovered apps (`--scope`) |
| `test [app]` | Run the workspace or app test script |
| `sync` | Update host remotes (`--hosts`), declarations (`--types`) and the manifest; supports `--dry-run`, `--diff`, `--check`, `--json` |
| `status`, `graph`, `inspect <app>` | Inspect project topology |
| `deps`, `check`, `doctor` | Inspect shared dependencies, validate ports/names, run health checks |
| `config` | `--show`, `--get`, `--set --value`, `--validate`, `--edit` |
| `migrate` | Inspect/apply the manifest migration (`--check`) |

Run `mfe-forge <command> --help` for exact options and the [CLI reference](https://rez-rayan-zin-eddine.github.io/mfe-forge/cli) for current limitations (for example, `build --analyze` and the `test` mode flags are not implemented yet). Use `--json` for automation.

## Configuration

`mfeforge.config.ts` (or `.js`) exports a plain object:

```ts
export default {
  name: 'my-platform',
  defaults: { packageManager: 'bun' },
  federation: { shared: ['react', 'react-dom', 'react-router-dom', 'zustand'] },
  dev: { portRange: [3000, 3999] },
}
```

The TypeScript loader does not run a compiler: comments, imports, type annotations, `as`/`satisfies` and `defineConfig(...)` are supported, but imported values are not resolved. See the [configuration guide](https://rez-rayan-zin-eddine.github.io/mfe-forge/config).

## Project structure

```
my-project/
├── apps/
│   └── checkout/
│       ├── host/           # Host application (shell)
│       └── cart/           # Remote MFE
├── packages/               # Shared packages / libraries / design system
├── mfeforge.config.ts
├── mfe-forge.manifest.json # Generated by status/sync
└── package.json
```

## Runtime packages

| Package | Description |
| --- | --- |
| [`@mfe-forge/core`](https://www.npmjs.com/package/@mfe-forge/core) | Error boundary, event bus, `RemoteLoader`/`LazyRemote` with bounded cache, remote registry |
| [`@mfe-forge/router`](https://www.npmjs.com/package/@mfe-forge/router) | Cross-scope navigation, route-change events, route generation, guards |
| [`@mfe-forge/store`](https://www.npmjs.com/package/@mfe-forge/store) | Global and scoped Zustand stores with event-bus sync |
| [`@mfe-forge/design`](https://www.npmjs.com/package/@mfe-forge/design) | Design tokens and CSS custom properties |
| [`@mfe-forge/testing`](https://www.npmjs.com/package/@mfe-forge/testing) | `renderMFE`, remote mocks, polling and Playwright helpers |
